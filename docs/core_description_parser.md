# Чистый парсер описаний керна

Этап 2 реализован пакетом `core_description`. Пакет не импортирует Qt, модели БД
или сервисы приложения и возвращает промежуточные dataclass-модели
`ParsedCoreDocument` и `ParsedCoreInterval`.

## Запуск

```bash
python -m core_description document.docx [second-document.doc]
```

Команда печатает JSON-массив. Ошибка одного файла записывается отдельным объектом
с полем `error`, остальные документы продолжают обрабатываться; при наличии ошибок
код завершения равен `1`. Поле `file_hash` всегда рассчитывается по исходному файлу,
в том числе до конвертации старого DOC.

Из Python:

```python
from core_description import parse_core_document

result = parse_core_document("document.docx")
print(result.to_dict())
```

## Поддерживаемая структура

- отдельные колонки верхней и нижней границы (`От`/`До` и алиасы);
- единая колонка диапазона с точкой или запятой и любым типом тире;
- одно- и двухстрочные заголовки, включая горизонтально объединённые ячейки;
- необязательные колонки геологического индекса и проявления;
- номер скважины и площадь в абзаце либо в соседних ячейках таблицы;
- номера с буквами и пробелами, например `10 Вр`, сохраняются целиком;
  подписи вида «Скважину документировал» и другие словоформы не принимаются
  за метку номера. Поддерживаются `Скважина`, `Скважины`, `Скв.` и `№ скв.`;
- площадь без подписи в шапке: «… поднятие», «… месторождение», «… структура»,
  а также обратный порядок слов — «поднятие Мельничное», «месторождение Северное»,
  «структура Южная» (включая двоеточие после типа); «Нефтеперспективный объект №58»
  и аналогичные обозначения объекта. Исходное название сохраняется вместе с типом;
- отдельное название площади в третьей непустой строке до первой таблицы
  с предупреждением `area_name_from_third_line`;
- если площадь не определилась в документе — название непосредственной папки
  исходного файла с предупреждением `area_name_from_directory`. Название из
  документа имеет приоритет. Для `.doc` используется исходная папка до конвертации,
  при рекурсивной загрузке — своя папка каждого файла. Если в документе были
  противоречивые названия, предупреждение `area_name_ambiguous` также сохраняется;
- даты начала и окончания бурения и альтитуда устья из абзацев и соседних ячеек
  таблиц перед таблицей керна; исходные строки сохраняются вместе с нормализованными
  значениями, неполные и ошибочные даты не дополняются вымышленным днём;
- подписи `Описал` и `Описал геолог` в конце документа;
- сохранение исходного описания и координат строки в документе.

Строки без границ, с одной границей, обратным или нулевым интервалом возвращаются
с диагностикой в `errors` и `selected_by_default=false`, а не отбрасываются. Нулевая
строка с именованной границей дополнительно получает `named_boundary_not_imported`.

## Семантический разбор (этап 3)

После структурного разбора каждая строка обогащается полями `rocks`,
`oil_saturation`, `confidence` и `semantic_matches`. Для каждой породы сохраняются
исходное совпадение, каноническое имя, отношение (`primary`, `secondary`,
`interlayer`, `interbedding`, `inclusion`) и идентификаторы сработавших правил.
`semantic_matches` содержит позиции совпадений и позволяет объяснить результат.

Правила находятся в `core_description/dictionary.json`, а их формальная схема — в
`core_description/dictionary.schema.json`. Версия словаря записывается
в `dictionary_version` результата. Загрузчик проверяет схему, категории, типы
шаблонов, регулярные выражения и уникальность идентификаторов. Отрицание имеет
приоритет над положительным признаком; неопределённые и локальные формулировки
добавляют предупреждение и снижают уверенность. Словарь можно расширять без
изменения алгоритма.

Словарь версии `1.2.0` распознаёт падежные формы и множественное число названий
пород. Нефтенасыщенность и битумонасыщенность обрабатываются как один признак:
`слабо` → `weak`, `средне` → `medium`, `интенсивно` / `сильно` → `intense`.
Учитываются полные и краткие формы прилагательных, слитное и раздельное написание.
Диапазоны сохраняются отдельно: `weak_to_medium`, `medium_to_intense`,
`weak_to_intense`. Например, «Песчаники … от средне до интенсивно битумонасыщенные»
даёт основную породу `sandstone` и насыщенность `medium_to_intense`.
Диапазоны доступны в фильтре импорта и при выборе нефтенасыщенных интервалов;
исходная формулировка и позиции совпадений сохраняются в `semantic_matches`.

В словаре 22 вида пород:

| Порода | Каноническое значение |
| --- | --- |
| Песчаник | `sandstone` |
| Глина | `clay` |
| Известняк | `limestone` |
| Доломит | `dolomite` |
| Аргиллит | `claystone` |
| Алевролит | `siltstone` |
| Мергель | `marl` |
| Конгломерат | `conglomerate` |
| Гравелит | `gravelite` |
| Брекчия | `breccia` |
| Песок | `sand` |
| Алеврит | `silt` |
| Мел | `chalk` |
| Опока | `opoka` |
| Трепел | `tripoli` |
| Диатомит | `diatomite` |
| Туф | `tuff` |
| Уголь | `coal` |
| Сланец | `shale` |
| Гипс | `gypsum` |
| Ангидрит | `anhydrite` |
| Каменная соль | `rock_salt` |

Прилагательные вроде «глинистый», «алевритистый» и «углистый» не создают отдельную
породу. Для прослоев также распознаются «с прослоем», «с прослойками»,
«с прослойкой», «с тонкими прослоями», «с тонкими прослойками», «тонкими прослойками».

Перед общим словом «битумонасыщенные» / «нефтенасыщенные» допускается несколько
степеней, соединённых запятой, союзами, дефисом, тире или косой чертой.
Сохраняется диапазон от минимальной до максимальной степени независимо от порядка:

- «слабо и средне битумонасыщенные» → `weak_to_medium`;
- «средне, местами интенсивно битумонасыщенные» → `medium_to_intense`;
- «интенсивно-средне-слабо нефтенасыщенные» → `weak_to_intense`.

«Местами» и «участками» добавляют предупреждение о локальности. Связь степеней
не проходит через другие свойства породы: «интенсивно трещиноватые, слабо
битумонасыщенные» даёт `weak`. Отдельные предложения и описания нескольких пород
не объединяются этими правилами в общий диапазон.

## DOC и безопасность

Старые `.doc` преобразуются установленным LibreOffice/soffice в отдельном временном
каталоге, который удаляется после разбора. При отсутствии конвертера возвращается
явная ошибка. DOCX читается как Open XML без выполнения макросов и перехода по
внешним ссылкам. Для защиты от zip bomb ограничены число элементов архива, общий
распакованный размер и размер `word/document.xml`.
