# Модель БД и сервисы импорта описаний керна (этап 4)

Этап добавляет таблицы `core_description_document`, `core_description_interval` и
`core_description_rock`. Исходный Word-файл в БД не записывается: документ хранит
SHA-256, имя и формат источника, исходные поля шапки и подписи, версии парсера и
словаря, способ сопоставления со скважиной и диагностический JSON. Интервалы и
распознанные породы удаляются каскадно вместе с документом.

Миграция `1e2f3a4b5c6d` объединяет две существовавшие ветви Alembic и поддерживает
`upgrade`/`downgrade`. Ограничение БД и повторная проверка в сервисе требуют
`top_depth < bottom_depth`; уникальный SHA-256 не допускает молчаливого повторного
импорта.

Миграция `2f3a4b5c6d7e` добавляет к интервалам поля `thickness` (мощность, м)
и `geological_index_raw` (геологический индекс). Для существующей БД перед
запуском обновлённой программы выполните `alembic upgrade head` из каталога
проекта с настройками нужной базы. Старые интервалы сохраняются; новые поля
в них остаются пустыми. Сервис сохраняет значения из документа либо ручные
правки предпросмотра, проверяя, что мощность конечна и неотрицательна.

## Сопоставление и проверка дублей

Функция `core_description.database.match_well(session, well_name, area_name, document=parsed_document)`:

1. нормализует регистр, `ё/е`, Unicode, пробелы и служебную пунктуацию;
2. для предпросмотра с `document` автоматически выбирает только однозначную
   скважину с точным номером и минимум двумя совпавшими признаками;
3. при одинаковых номерах уточняет результат по значениям `WellOptionally`
   (**Data of Well**): `Площадь`, `пл.`, `area`, `Залежь`, `Месторождение` и другим
   категориям; название площади ищется в значениях независимо от категории;
4. учитывает грамматические варианты названий («Сарабикуловское поднятие» /
   «Сарабикуловский») и номер объекта («Нефтеперспективный объект №58» /
   «Объект 58» / «58»); для названий использует сходство строго выше 50%,
   для номеров объектов — точное совпадение;
5. нечёткие совпадения возвращает только как предложения для ручного выбора,
   отдавая приоритет подходящей площади перед ограничением в десять вариантов.

При передаче `document` дополнительно сравниваются нормализованные даты начала
и окончания бурения и альтитуда устья. Даты берутся из соответствующих категорий
`WellOptionally`, альтитуда — также из `Well.alt`. Однозначное совпадение номера
и минимум двух из четырёх признаков (площадь/участок, начало бурения, окончание
бурения, альтитуда устья) позволяет выбрать скважину с методом `exact_name_identity`.
Каждый признак учитывается один раз независимо от количества его записей в БД.
Остальные признаки могут различаться. Несколько подходящих записей или менее
двух совпадений требуют ручного выбора. Совпадение месяца без дня отмечается как
частичное и не учитывается в счётчике; допуск для альтитуды — 2 м включительно.
Отсутствующие значения не считаются совпадениями.
Значения категорий бурения и альтитуды не используются как названия площадей.

В `diagnostics` документа сохраняются исходные и нормализованные сведения
`well_identity`, результат сравнения `well_comparison` с процентом сходства
площади и применённые пороги `well_match_policy`. Новые столбцы и миграция БД
не требуются.

Площади загружаются для точных совпадений по имени либо для нечётких предложений.
Если площадь не указана, загружаются только десять лучших нечётких предложений;
если указана, площадь учитывается до ограничения списка. Идентификаторы разбиваются на пакеты по 500,
чтобы не превышать лимит SQL-параметров SQLite даже при большом числе
скважин с одинаковым именем. Это ограничение относится к сопоставлению
с базой и не зависит от исходного формата документа (`.doc` или `.docx`).

`check_duplicates` отдельно сообщает точный дубль документа по хешу и пересечения
его интервалов с ранее сохранёнными интервалами той же скважины. Наличие
пересечения само по себе не запрещает сохранение: решение остаётся за будущим
интерфейсом предпросмотра.

## Сохранение

```python
from core_description.database import save_core_import

result = save_core_import(
    session,
    parsed_document,
    well_id=selected_well_id,
    selected_interval_ids={"0:7", "0:8"},
    edits={"0:8": {"oil_saturation": "medium"}},
    duplicate_policy="reject",
    match_method="manual",
    match_confidence=1.0,
)
```

Устойчивый идентификатор строки имеет вид `"<индекс таблицы>:<индекс строки>"`.
Для внутреннего кода также принимается пара индексов. Сервис заново проверяет
скважину, непустое описание и конечные возрастающие глубины, сохраняет только
выбранные строки и фиксирует ручные правки. `duplicate_policy="reject"` является
безопасным режимом по умолчанию; `"replace"` явно заменяет документ и его дочерние
записи. Любая ошибка вызывает `rollback`, успешная операция — один `commit`.
