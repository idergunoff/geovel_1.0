# Импорт описаний керна: инструкция пользователя и администратора

## 1. Назначение и ограничения

Импорт переносит интервалы и исходные описания керна из `.docx` и `.doc` в уже
существующую скважину GeoVel. Он **не создаёт скважины**, не выполняет OCR и не
угадывает пропущенные глубины. Исходный Word-файл в базе не хранится; для аудита
сохраняются его имя, SHA-256, исходные значения шапки и подписи, полный текст
выбранных интервалов и версии парсера и словаря.

Перед рабочим импортом сделайте резервную копию БД. Для `.doc` установите
LibreOffice. GeoVel ищет его в `PATH` и в стандартных каталогах установки
Windows/macOS. Для переносной или нестандартной установки укажите полный путь к
`soffice` в переменной окружения `LIBREOFFICE_PATH`. `.docx` читается напрямую.

## 2. Пошаговый импорт

1. Откройте вкладку **Layer, Well** и нажмите **Керн**.
2. Нажмите **Добавить файлы…** или **Добавить каталог…**. Для рекурсивного
   поиска заранее включите **включая подкаталоги**.
3. Дождитесь окончания обработки. **Отменить обработку** прекращает запуск новых
   файлов; уже разобранные результаты остаются в предпросмотре.
4. Выберите строку документа. Проверьте имя скважины, площадь, автора и общие
   предупреждения. Ошибка одного файла не блокирует другие.
5. Проверьте поле **Скважина БД**. Автоматический выбор допустим только при
   однозначном точном соответствии. При сообщении «Требуется ручной выбор»
   выберите правильную скважину; нечёткое совпадение не подтверждается само.
6. Проверьте каждый выбранный интервал по оригиналу. Редактируются верх, низ,
   породы, нефтенасыщенность и уверенность. Полный исходный текст не редактируется.
   Подсказка ячейки показывает сработавшие правила словаря.
7. Используйте фильтры и команды выбора. Фильтр лишь скрывает строки и не меняет
   их флажки. **Вернуть автоматические значения** действует на выделенные строки.
8. Сверьте итоговый счётчик и нажмите **Сохранить выбранные**. Каждый документ
   пакетного импорта сохраняется отдельной транзакцией.
9. При необходимости экспортируйте отчёт в JSON/CSV. Отчёт содержит путь,
   статус, ошибку, длительность и число интервалов, но не полные описания.

## 3. Статусы и предупреждения

| Состояние | Действие пользователя |
|---|---|
| `готово` | Сверить с оригиналом; строка может быть выбрана автоматически. |
| `требует проверки` | Проверить предупреждение, сопоставление и распознанные значения вручную. |
| `ошибка` | Исправить документ либо исключить строку из сохранения. |
| `не сопоставлена` | Выбрать существующую скважину БД. |
| `дубликат` / ошибка повторного импорта | Не повторять импорт; замену выполнять только по утверждённому регламенту. |

Низкая уверенность, неопределённая формулировка, отсутствие автора и локальный
признак («местами») не должны подтверждаться автоматически. Отрицание признаков
нефти имеет приоритет перед положительным совпадением. Значения глубин должны
быть конечными и удовлетворять `верх < низ`.

## 4. Частые проблемы

- **LibreOffice не найден.** Установите LibreOffice или задайте полный путь к
  `soffice`/`soffice.exe` в переменной окружения `LIBREOFFICE_PATH`, затем
  перезапустите GeoVel. Альтернативно преобразуйте `.doc` в `.docx` на доверенной
  машине. Не переименовывайте расширение файла.
- **Не найдена таблица/шапка.** Сверьте документ с поддерживаемым шаблоном; не
  добавляйте глубины вручную без проверки исходника.
- **Несколько скважин с одним номером.** Используйте площадь и выберите запись
  вручную. Импорт никогда не должен создавать новую скважину для устранения
  неоднозначности.
- **Часть пакета завершилась ошибкой.** Сохраните корректные документы,
  экспортируйте отчёт, исправьте только ошибочные файлы и повторите их отдельно.
- **Файл уже импортирован.** Сравните SHA-256 и существующие интервалы. Обычный
  режим безопасно отклоняет точный дубль.

## 5. Администрирование словаря

Рабочий словарь находится в `core_description/dictionary.json`, его JSON Schema —
в `core_description/dictionary.schema.json`. Изменение словаря должно проходить
code review и тестирование; редактирование общего файла конечным пользователем в
интерфейсе не предусмотрено.

Для нового правила:

1. создайте уникальный стабильный `id` вида `категория.значение.NN`;
2. выберите разрешённую категорию: `rock`, `rock_relation`, `oil_indicator`,
   `oil_saturation`, `negation`, `uncertainty` или `ignore`;
3. задайте каноническое значение, непустой список `patterns`, тип `word`,
   `phrase` или `regex`, целочисленный приоритет и `enabled`;
4. для регулярного выражения избегайте широких шаблонов и проверьте ложные
   срабатывания; отрицаниям назначайте приоритет выше положительных признаков;
5. увеличьте поле `version` по SemVer и добавьте тест с положительным и
   отрицательным примером;
6. выполните проверки ниже и проведите ручную сверку на обезличенной копии.

```bash
PYTHONPATH=. python -c "from core_description.semantics import load_dictionary; d=load_dictionary(); print(d.version, len(d.rules))"
PYTHONPATH=. pytest -q tests/test_core_description_parser.py
```

Ошибки неизвестной категории, повторяющегося `id`, пустого шаблона или неверного
регулярного выражения блокируют загрузку словаря. Откат выполняется возвратом
предыдущего JSON и его версии; уже сохранённые документы сохраняют использованную
версию и не переразбираются автоматически.

## 6. Приёмка релиза

Перед выпуском выполните регламент из
[`core_description_stage7_acceptance.md`](core_description_stage7_acceptance.md):
модульные и интеграционные тесты, полный регрессионный прогон, замер
производительности и ручную сверку разрешённых оригиналов. Оригиналы с
конфиденциальными данными не добавляйте в Git и не прикладывайте к отчёту.
